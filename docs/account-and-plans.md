# 账户余额与第三方套餐

## 账户与套餐面板

看板上的「账户与套餐」是一张面板并排两栏：左边官方余额，右边第三方套餐。套餐那一栏顶部
有一枚**「当前监看」切换器**：

- 选项是「自动（最紧）」加**每一家已配置的厂商**，**取数失败的那一家也会列出来**，
  方便你切过去看它的失败原因；
- 「自动」的含义就是在全部可用厂商里挑最紧的那个窗口；
- 被监看的那一家区块会带一道粉色标记与「当前监看」徽标。

这个选择只存在浏览器本地，不影响宿主是否发请求、也不影响预警判定。

## 官方账户余额

看板里的「账户与套餐」卡片，以及输入框正下方费用条旁的一枚余额（当来源是官方 API 时），
都来自官方 [`GET /user/balance`](https://api-docs.deepseek.com/api/get-user-balance)。

| 事项 | 说明 |
|---|---|
| 查询哪个账户 | 只查 **DSH 自己给官方 provider 用的那把 Key** 对应的账户（凭据引用默认 `DEEPSEEK_API_KEY`，可在 `llm-deepseek` 设置段里改）。暂不支持查询任意账户。 |
| 端点 | settings 段里显式配置的 `baseURL`，否则官方公网地址。 |
| 币种 | 接口返回几种就显示几种（可能同时有 CNY 与 USD），**不做汇率换算**。 |
| 刷新 | 缓存 60 秒；看板上点「刷新」会强制重取。 |
| 拿不到时 | 明确显示原因（没配 Key / 请求失败 / 已关闭），**不会**显示成 `¥0`。 |
| 关闭 | 卡片里的开关；关掉后不再发请求。`DSH_PIXEL_BALANCE=0` 可硬性关闭。 |
| 费用条那一枚 | 只在**当前模型来源是官方 API**（或来源认不出、且没手动指定套餐）时显示。走套餐时显示那一家的额度。 |

余额为负数（例如 `-¥0.79`）是官方接口真实会返回的状态，表示已欠费，界面照实显示。

## 订阅套餐额度

看板里的那一栏监控第三方 Coding Plan 的剩余额度，按窗口画进度条。
费用条旁边那一枚也用它——当**当前模型来源**属于某一家时显示那一家的最紧窗口。

| 厂商 | 窗口 | 备注 |
|---|---|---|
| 智谱 GLM Coding Plan | 5 小时、每周 | 官方**没有**月度额度，卡片里会写明 |
| Command Code | 5 小时、每周、每月 | 月度按套餐（Go `$10` / GOAT `$70` / Pro `$80` / Max …）换算成百分比 |
| 火山方舟 Agent / Coding Plan | 5 小时、每周、每月 | 自动探测两种订阅：Agent Plan 给**绝对值**，Coding Plan **只给百分比** |

### 月度那一栏是怎么算出来的（Command Code）

Command Code 的额度接口对 5 小时与每周都同时给了「已用」和「上限」，所以百分比直接算得出来；
**月度却只给一个剩余余额**（如 `$65.55`），既没有已用、也没有总额。它需要另外两个接口拼起来：

| 接口 | 给什么 |
|---|---|
| `GET /alpha/billing/credits` | 5 小时 / 每周的 `used` + `cap`，以及月度的**剩余**信用额 |
| `GET /alpha/usage/summary` | **本计费周期已用**信用额（`totalMonthlyCredits`） |
| `GET /alpha/billing/subscriptions` | **套餐身份**（`planId`，如 `individual-goat`）与计费周期（`currentPeriodEnd`） |

于是月度百分比 = 已用 ÷ （已用 + 剩余）。套餐身份决定了名义月额度，`planId` 也用在卡片上的
套餐徽标（`GOAT`）。已收录的档位与名义月额度：

| planId | 套餐 | 月额度 | 5 小时 | 每周 |
|---|---|---|---|---|
| `individual-go` | Go | `$10` | `$3` | `$6` |
| `individual-goat` | GOAT | `$70` | `$14` | `$35` |
| `individual-pro-v1` | Pro | `$80` | `$16` | `$40` |
| `individual-max` | Max 10× | `$150` | `$45` | `$90` |
| `individual-ultra` | Max 20× | `$300` | `$90` | `$180` |
| `teams-pro` | Team Pro | `$40` | `$12` | `$24` |

三条规则，都是为了让界面不撒谎：

- **拿不到「已用」就按名义额度反推**（已用 = 名义额度 − 剩余），并在卡片上标注这是推算；
- **两个接口的数对不上名义额度时，一个百分比都不给**——跨计费周期或中途换套餐时，「已用 + 剩余」
  可能来自不同周期，相加看着合理却差着几十个百分点。这一栏此时只显示 `—` 与原因；
- **未收录的套餐不做推算**：没有名义额度这把尺子，就只用「已用 + 剩余」，两者都拿不到时显示 `—`。

> 官方的额度口径随时可能变，[定价页](https://commandcode.ai/docs/resources/pricing-limits)是权威。
> 上表是 2026-09 的取值；对不上时插件会退回「只报余额」，而不是继续报一个错的百分比。

**每个窗口都会标出重置时刻**，形如 `10/14 20:26 重置（23 天 9 小时后）`——绝对日期按站点时区
渲染，括号里是剩余时间。月度这种长周期，光有「还剩 23 天」还得自己算日子，所以两个都给。
重置时刻来自 `subscriptions` 的 `currentPeriodEnd`（一个 **ISO 日期串**），5 小时与每周则用
`credits` 里的数字时间戳；两种形状插件都认。任何一栏拿不到时刻时，那一栏就**不显示**这句话，
而不是编一个日期出来。

### 面板只显示你真正在用的那几家

随着接入的第三方厂商变多，全列出来会让面板越来越长，而其中大半是「你根本没配凭据」
的噪音。因此：

- **配好凭据的（或配过但出问题的）一直显示**在最上面；
- **从没配过凭据的**收进「未配置的厂商」折叠区，标题行写着有几家，点开能看到
  每一家的用途与配法——**不是删掉**，插件支持哪些家始终查得到；
- **一家都没配时折叠区默认展开**：那时上面是空的，收起会让新用户什么都看不到；
- **你正在监看、或刚在切换器里点中的那一家，永远留在上面**——点了它却在下面找不到，
  是最让人困惑的一种界面。

> 判据是「**有没有配过**」，不是「成功还是失败」。**配过但坏了**的那一家（鉴权被拒 /
> 接口失败）不会因为失败就被收起来——那正是你需要看到原因的时候。

### 这些接口是未文档化的

**三家都没有公开文档化的额度 API。** 本插件用的是它们**前端 / CLI 自己在用**的内部接口，
因此**可能随时失效**。一家失败只标那一家，其余各家与看板其余部分照常工作，
界面上也明确写「未文档化的内部接口」。

### 额度百分比可以超过 100

套餐额度用超时官方会给出 >100 的百分比，界面**照实显示**并单独标出「已超限」。

## 凭据怎么配

| 厂商 | 凭据引用 | 去哪拿 | 自动发现 |
|---|---|---|---|
| 智谱 | `ZHIPU_CODING_API_KEY` | [智谱「个人编程套餐」](https://www.bigmodel.cn/coding-plan/personal/usage) | —（智谱没有官方 CLI 凭据文件） |
| Command Code | `COMMAND_CODE_API_KEY` | [Command Code 工作台](https://commandcode.ai/studio) | `~/.commandcode/auth.json` 的 `apiKey` |
| 火山方舟 | `VOLC_ACCESS_KEY_ID` + `VOLC_SECRET_ACCESS_KEY` | [火山引擎 API 访问密钥](https://console.volcengine.com/iam/keymanage/) | —（**两把都要配**） |

拿到的值有**两种**写法，任选其一（同名即通用）：

**写法一：写进 DSH 凭据文件**（推荐）

文件是 `<DSH_HOME>/.credentials.yaml`（`DSH_HOME` 默认 `~/.dsh`），
在 `refs:` 段下按名字加行：

```yaml
version: 1
refs:
  VOLC_ACCESS_KEY_ID: AKLT...
  VOLC_SECRET_ACCESS_KEY: ...
```

DSH 会**自动重载**这个文件，因此改完不用重启——等下一次额度刷新（约 30 秒）
或点一下看板的「刷新」即可。

**写法二：设成同名环境变量**

写进 `<DSH_HOME>/.env` 或项目目录的 `.env`，或者启动 `dsh` 前 export。
这两条路都要**重启 `dsh`**：环境值在启动时就快照固定了。

优先级是**启动时环境 > 凭据文件 > 项目 `.env` > `<DSH_HOME>/.env`**。

> **为什么不能直接在「设置 → 模型」里填？**
> 那个页面只把你填的 Key 存到它自己按路由名派生的 `<路由名>_API_KEY` 之下
> （如 `VOLCENGINE_API_KEY`），而火山要的是固定的 `VOLC_ACCESS_KEY_ID` /
> `VOLC_SECRET_ACCESS_KEY`——**这两个名字不可能由那条规则推导出来**。
> 所以对火山的 AK/SK，凭据文件（或环境变量）是唯一可靠的去处。
> 看板里每一家的「这家凭据怎么配」会直接把**这台机器上的完整路径**显示出来。

Command Code 若已装 CLI 并登录过，插件会**自动读**该文件，无需额外配置；
`COMMANDCODE_HOME` 可覆盖它的目录。

> **智谱的 Key 必须是「编程套餐专属」的那一把**——在「个人编程套餐」里新建，
> 与平台普通 API Key **不通用**。用错的表现是：标准模型调用能过，但额度查询报
> `Authentication Failed`。界面上会显示凭据尾 4 位（如 `…a1b2`），便于你确认读到的
> 是哪一把。

> **火山方舟要的是另一套凭据：AccessKey ID / Secret Access Key，不是推理用的 `ark-` Key。**
> 用推理 Key 去查的表现是：网关在格式层就拒（HTTP 400 / `InvalidAuthorization` 100024）。
>
> 这两把在**火山引擎账号的 IAM** 里创建（[API 访问密钥](https://console.volcengine.com/iam/keymanage/)，
> 也常写作「访问控制 → 访问密钥」），**不在方舟控制台里**——方舟控制台给的是
> `ark-` 开头的推理 Key，正好是本接口拒绝的那一把。Secret Access Key
> **只在创建时显示一次**，记得当场下载凭证。
