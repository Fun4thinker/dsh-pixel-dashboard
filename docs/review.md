# 使用复盘：钱和时间花在哪

## 四个页面，不是一张长报表

- **总览**：原有概览卡、时段与活跃日历、Token / 费用双趋势。原有布局保留，活跃口径改为人机对话轮次。
- **使用习惯**：全窗口（含归档）的 24 小时分布和星期 × 小时热力图。
- **资源去向**：近期未归档工作区、会话、工具的资源账目，可切换到窗口全部记录。
- **账户与模型**：套餐额度、模型分布和模型费用明细。

顶部 7 / 30 / 90 日作用于当前页面。分页位置按本机浏览器偏好保留；资源排行每页 8 项，不再用“展开全部”将页面无限拉长。

## 活跃度：人和 Agent 的对话，不是模型工作量

默认按用户输入或手动继续进入执行日志时的轮次计数；同一执行轮内的多条用户 steering 去重。自动目标续跑、智能体消息、子代理完成事件、对问答工具的答复不冒充新的人机对话。

- 活跃日历、连续活跃天数、小时习惯的默认强度均为对话轮次。
- 使用习惯可切换 Token 消耗（输入与输出累计），替代估算费用；小时分布、周热力图、最集中时段与周末占比均按 Token 数计算，不受模型价格差异影响。费用继续在资源去向中统计。
- 请求次数仍保留，明确表示模型执行工作量：一个对话轮次可以产生很多模型请求。
- 人机轮次按输入被接纳进入执行日志的时刻归日，并非键盘实际发送时刻；旧日志没有可辨来源时不猜测。
- 继承的日志前缀不会重复计作子会话的人机轮次和工具活动。

## 耗时：原始用时、等人、有效处理分别记账

配对同一执行轮的 `turn/start` / `turn/end`，保留毫秒精度：

```
有效处理耗时 = 原始轮次用时 − 等待用户区间
```

“等待用户”只能依据已知问答工具的调用生命周期近似推算。DSH 没有更细的持久化“用户开始阅读/提交答案”时间边界，因此界面明确标注**问答工具区间近似**，不宣称精确阅读时间。

- 重叠等待区间取并集，只扣相交部分，避免并行问答重复扣时。
- 已知轮次结束后，不将很晚到达的答复跨越空闲时间算入其他轮次。
- 有效时长允许为 0，不再强制采用 Chat 最少显示 1 秒的展示钳制。
- 停止、失败、未完成或没有有效起点的执行轮次不混入已完成时长。
- 按已完成执行区间与窗口、站点自然日/小时的交集分配耗时，不把整个历史会话或窗口外时长计入。
- 会话总时长、步骤诊断和工具耗时均排除相应问答等待；正常工具的真实执行不应被其他并行问答扣掉。
- 未返回调用显示未结算，不伪造完成耗时或参与最慢排行。

原始轮次用时、已扣等待与有效处理使用同一已完成计时集合，可相互核对。跨会话可能并行，累计量不是人的在线时长；步骤分解是独立诊断口径。

## 小时分布与步骤诊断各代表什么

使用习惯的有效耗时分布是**当前日期窗口内，所有自然日同一钟点的累计有效处理时长**。执行区间先扣除问答等待，再按站点本地小时切开，跨小时分摊；不是平均每轮、不是一天24小时的占比，也不是人的在线时间。例如一轮10:50–11:10，中间10:55–11:05为问答区间，则10点与11点各计5分钟。

步骤耗时主图区分模型调用（含准备、等待及生成）、工具执行、响应后的其他处理。`assistant/message` 是完整响应落盘，不是首字到达；旧版将消息后的收尾段标成“模型回复”，会误导为生成只占0%。兼容旧字段 `ttftMs`/`genMs`，但不再据此声称测得真正TTFT或生成时间。

可用的持久流记录另在折叠明细中呈现首输出前时长、接收输出区间及覆盖步骤数。打包流的时钟按 `time0` 加累计 `dt` 还原，重试分别计接收区间、不连接中间空档；缺测为未知，不补零。这些是本机接收观测，含准备/重试影响，不是模型内部思考或精确网络TTFT。

费用页标题只依据真实Agent运行事实显示运行中、空闲或未运行；原 `live` 字段仅代表会话加载。当前页面优先订阅原生会话状态，问答/审批待处理会单独提示；原生状态尚未知时不回落显示缓存的“运行中”。会话可继续，不能因本轮结束就认定整条会话永久完成。

## 资源去向的范围

默认 `recent`：仅已知未归档、且自身活动发生在当前时间窗口内的会话。继承的账本请求不用于证明子会话近期活跃；仅存在账本而没有本机日志/归档事实的记录不被猜成未归档。

切到 `all`：可查看窗口内全部账本记录，包括归档、归档状态未知与仅有账本的历史。它不是全部时间历史，仍服从顶部日期范围。

界面会显示隐藏的归档、非近期、归档未知数量，并分别呈现：

- 全窗口账本估算金额，便于与总览趋势对账。
- 当前筛选范围的金额和用量；隐藏记录未删除。
- 计时覆盖 X/Y 个会话；无计时不按零补齐，缺测不参与耗时合计。

工作区按规范化完整目录分组，同名末级目录不会合并。工作区内与顶层会话列表默认最近使用，点击列头可按最近使用、费用、有效时长、Token 或模型请求排序；新列默认降序，再点同一列切为升序，以箭头标明方向。缺测在两个方向都排末尾，不冒充 0。列表铺满可用宽度，并保留原地展开模型费用与逐日账目。资源页只突出费用、人机对话、有效处理三项，不再单列等待用户耗时卡；底层等待区间仍保留以正确扣时。

有可信团队拓扑时，可展开 Lead 与各成员的窗口消耗。团队只是归属视图，不把团队合计再次加进本会话或总览；成员同样遵守当前日期与 recent/all 范围，隐藏、窗口外及缺测计时会明确提示。没有可靠团队事实的普通会话不猜测分组。

工具可看来源、单次最慢、最近 30 次调用的时间与所属会话。展示条数不影响统计总数。

主会话不额外叠加成员合计。费用和请求继续沿用原账本口径，包含原账本已有的继承历史，不代表子会话新增支出；存在这类请求时明确提示。

## 加载与刷新

- 7 / 30 / 90 日 × 两种范围的有界内存缓存，相同窗口只保留一个进行中的请求。
- 首次加载使用与目标页面对应的图表/列表骨架，不使用一行短提示卡顶替整个页面。
- 切换范围时保留旧布局和旧数据原有范围标签，明确提示新范围正在加载，旧内容不可操作；不把旧数字换上新日期标签。
- 加载失败仍说明正在显示的日期与范围，可重试，不把错误显示成零账目。

## 输入框费用与账户卡片

输入框下仍使用紧凑胶囊，不将大卡片常驻一整行，也不挤占官方轮次和 Token 统计。点击费用与右侧账户各有详情入口，但任一时刻只打开一张卡片。

费用卡默认「费用」，「时间」是次级标签：展示当前会话全程（或同一团队）的已完成有效处理、问答等待、原始用时和计时覆盖。未完成问答不算机器执行；成员并行累计不代表实际经过时间或在线时长。切换标签时重新测量浮层尺寸，长卡片可滚动。

账户卡遵循当前模型来源绑定，分别显示可用余额与充值/赠送构成，或套餐各窗口的已用、剩余与重置。不同币种不混加；缺失比例显示未知而非 0%。自动回落/手动监看会说明来源，查询失败显示原因，不展示凭据。

## 工具来源的证据边界

DSH 历史工具事件不保存执行插件的 owner，当前工具注册也不公开 scope 精确的 owner API：

- `内置·匹配` / `第三方·匹配` 表示工具名与核实过的插件声明相符，不是历史执行归属确证；同名 scoped 工具可能覆盖它。
- 内置包含官方插件；第三方只收录明确声明。无法匹配保留来源未知，绝不默认第三方。
- 详情保留声明包和核对依据；注入的可信按会话/调用区分的来源证据优先。
- 不包装 DSH 工具注册器，不依赖其他插件的私有 owner 表。

工具调用按 `callId` 配对结果，PTC 子调用使用独立 ID 空间。工具不直接分摊模型费用，外部 API 收费不在本地 Token 估算内。

## 取数与隐私

只读接口 `GET /dsh-pixel/review?days=7|30|90&scope=recent|all`，响应 schema 为 2；默认 30 日、recent。`ledgerSummary` 是全窗口账本，`summary` 是当前范围。归档状态来自可选的官方工作区注册表，缺失时明确未知。

只缓存调用名、ID、轮次、时间、数值和状态等轻量事实，不保留调用参数、结果或助手正文。升级缓存格式后首次需要重扫，之后沿用增量派生缓存。数据不完整明确报错，不以零账目掩盖失败。

所有费用均为按模型单价折算，不是服务商账单，尤其不代表订阅套餐实际扣款。
