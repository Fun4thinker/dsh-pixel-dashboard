# 计费口径

> **所有金额都是「按官方单价估算」：假如这些 token 全部走官方 API，要花多少钱。**
> 它**不是**你的实际账单。
>
> 第三方中转与 Coding Plan（智谱 / Command Code / 火山方舟等）是**买断制**——
> 付费时一次性结清，不按 token 计费。所以它们的花费**不在此估算范围内**，
> 而不是「估算得不太准」。按 token 动态计费、余额会越用越少的只有官方 API，
> 那也正是这个估算要回答的问题。
>
> 中转站如果你确实按量被加价，直接在「设置 → 模型单价」里把那几个模型的单价改成
> 你实际被收的价（界面已不再提供「按提供商加价倍率」，配置文件里仍支持，见第四节）。

单位统一为 **元 / 百万 token**。外币价目（OpenAI / Anthropic / Google / xAI）按
**可配置汇率**折算成人民币后参与合计，界面上会标出「按汇率 X 折算」。

## 一、时段与分档

**高峰时段 = 周一至周五（不含中国法定节假日）9:00–12:00、14:00–18:00；
其余时段，包括全部周末与中国法定节假日全天，都是空闲时段，空闲价 = 高峰价的一半。**
费用按**每条请求发生时刻**分档计价。

### 法定节假日与调休上班日

官方对分时口径还有两条补充说明，插件都照办：

| 情形 | 怎么计费 | 例子（2026 年） |
|---|---|---|
| 法定节假日**全天** | 空闲 | 10 月 1 日（周四）、10 月 2 日（周五）的白天也是空闲 |
| **调休上班的周末** | 仍按空闲 | 9 月 20 日（周日）、10 月 10 日（周六） |

第一行是最容易漏的一条：国庆那几天里有工作日，只看星期几会把它们的白天算成高峰，
金额**整整高一倍**，而且不会报错。看板「时段与计费」卡片里因此单列一行
**法定节假日**，写明「全天按空闲计费」以及这份日历**收录到哪一年**——跨到表外年份时
会退回按星期几判断，界面照实说明，而不是假装知道。

第二行说明**为什么日历里不需要记录调休上班日**：调休上班的那天本来就是周末，
而周末本来就是空闲，把它当工作日反而会与官方口径正好相反。

节假日表在 `lib/holidays.js`，按《国务院办公厅关于……部分节假日安排的通知》逐段照抄。
下一年度的通知（惯例在上一年 11 月发布）到手后追加一组即可，其余代码不用动。

### 「空闲价是高峰价的一半」只是 DeepSeek 的规则，不是通用规则

智谱、千问、OpenAI、Anthropic、Google、xAI、MiniMax **都不分时**：官方价目表只有一列价。
价目条目用 `flat: true` 标明这一点，因此**界面上它们只显示一列 token、一个单价**——
硬摆一对相同的「空闲 / 高峰」数字纯属噪音，还会让人以为有折扣。

> 智谱 Coding Plan 的「非高峰 50%」是**订阅积分**口径（高峰 = 周一至周五 14:00–18:00，
> 与 DeepSeek 的窗口**不同**），按积分而非金额抵扣，因此不进这个按量估算。

### 分档定价的模型标「按最低档」

有些官方按**输入长度**分档（GLM-4.6V 的 32K、千问的 32K/256K、Gemini 的 200K、
Claude Haiku 的 100K、MiniMax 的 512K）。账本里没有可靠的逐请求输入长度，
因此这类模型只按**最低档**估算并标 `tiered`，界面注明「按最低档」。
取错档会低估数倍，所以宁可标注不精确，也不假装精确。

## 二、价目表（按厂商）

每条价目的字段：`label`（官方模型名）、`vendor`、`currency`、`flat`、
`cacheHit`（缓存命中输入）、`cacheMiss`（未命中输入）、`output`、
`cacheWrite`（缓存写入，可选）、`asOf`（采集月份）、`source`（官方定价页）。
下表的数字顺序是 **缓存命中 / 未命中 / 输出**；`空闲/高峰` 用斜杠表示，只有一个数即不分时。

### DeepSeek — 人民币，分时

来源：<https://api-docs.deepseek.com/zh-cn/quick_start/pricing/>（截至 **2026-11**）

| 模型键 | 显示名 | 缓存命中 | 未命中 | 输出 |
|---|---|---|---|---|
| `deepseek-flash` | DeepSeek Flash | 0.02 / 0.04 | 1 / 2 | 4 / 8 |
| `deepseek-v4-pro` | DeepSeek V4 Pro | 0.15 / 0.30 | 4.5 / 9 | 13.5 / 27 |

`cacheWrite`（见下文 OpenAI / Anthropic），**有就用它**，没有才退回这条规则。

## 三、汇率（美元价目怎么参与合计）

`usdToCny` 是**用户可改**的一项设置，默认 **7.3**。

- 内置美元条目（OpenAI / Anthropic / Google / xAI）在**生效视图**里按它折成人民币，
  因此合计、明细、逐日、逐会话用的是**同一个汇率**——不会出现「合计按 7.3、明细按 7.2」。
- 界面上美元条目会标「按汇率 7.3 折算」，悬停还能看到官方原价。
- 改汇率会同时改变所有美元条目的金额；**人民币条目完全不受影响**。
- 早先这些条目是「写死 ×7.2 的人民币值」，那个 7.2 既不可改、也看不出出处，
  与用户自己的账单对不上时无从解释。现在价目表存**原币**（`currency: 'USD'`），
  原币数字保留在 `native` 里，折算只是展示与计价时的一步。

## 四、按提供商加价倍率（**已从界面移除，仅配置文件支持**）

> 用户明确表示「倍率这个功能也没用」，因此**设置页里不再有这一节**。
> 能力仍保留在 `custom-rates.json` 里（老用户的配置不会失效，也不会被覆盖），
> 需要时手改文件即可。下面是要填的格式。

按**提供商路由名**配置一个倍数，默认 **1**：

| 你填 | 含义 |
|---|---|
| `1` 或留空 | 按官方价计（默认） |
| `1.2` | 那一家在官方价上加价 20%（中转站常见） |
| `0.9` | 打折通道 |

- 只影响**金额**，不影响用量与归属；用量表、模型分布仍按真实 token 显示。
- 与「我的单价」是两件事：单价改的是**某个模型**的价，倍率改的是**某一家提供商**的价。
  两者可以叠加（`该模型单价 × 该家倍率`）。
- 填 0 或负数会被拒绝并点名是哪个提供商——`0` 会让整家用量变成「免费」，
  界面上看不出来，比报错危险得多。

## 五、自己补一个价

内置价目表是随插件发布的。新模型发布得很勤，而「我用的模型没有价」的表现是它被标成
**「估算价」**并按 Flash 兜底折算——数字有、也不报错，只是错的。

补价有三个入口，改完**立刻生效**（刷新看板即可，不必重启）：

**入口一：看板 →「设置」→「单价」页**（整页，能一次看全）

| 这一页能做什么 | 说明 |
|---|---|
| 按**提供商分页** | 左栏只列**你自己接的那几家**（来自 DSH 的模型配置，按用量排序），右栏是那家的模型单价；没接的厂商不会平铺出来 |
| 搜索 | 只**在当前提供商内**过滤；模型键、显示名任一命中，大小写与分隔符都能对上（搜 `glm53` 也能找到 `glm-5.3`） |
| 改一条价 | 点某一行的「改单价」才展开表单（浮层）：填「未命中 / 输出」两档即可；分时定价的厂商再填「空闲 / 高峰」 |
| 恢复官方价 | 我改过的那一行会多一枚「恢复官方价」——删掉覆盖，回到插件内置的价 |
| 编辑时按**原币**填 | 美元条目显示的是官方原价（$2），不是折算后的 14.6——否则下次改汇率就全乱了 |
| 汇率 | `usdToCny` |
| 导入 / 导出 JSON | 导出会顺带复制到剪贴板，方便搬到另一台机器 |

**入口二：费用明细里那一行的「改单价」**——只看某一条时用它，点开是浮层，只编辑那一个模型。

**入口三：直接改文件**——一次补一批、或想放进版本管理：

> 表单**默认不展开**：一进设置页就把几十个模型的六格价格全铺开，会把「有哪些模型」
> 这条主线淹掉，所以清单是默认态、表单点开一次编辑一条。

路径 `$DSH_HOME/plugins/dsh-pixel-dashboard/custom-rates.json`（`DSH_PIXEL_RATES` 可覆盖），
界面里也会显示这台机器上的完整路径。

```json
{
  "usdToCny": 7.3,
  "markup": { "commandcode": 1.2 },
  "rates": {
    "gpt-6-alstra": {
      "label": "GPT-6 Alstra",
      "vendor": "OpenAI",
      "cacheMiss": 10,
      "output": 40,
      "cacheHit": 1
    },
    "some-tiered-model": {
      "label": "Some Tiered",
      "currency": "USD",
      "cacheHit": { "idle": 0.5, "peak": 1 },
      "cacheMiss": { "idle": 5, "peak": 10 },
      "output": { "idle": 20, "peak": 40 }
    }
  }
}
```

- 写一个数 = 不分时；写 `{ peak, idle }` = 分时（**两个值都照写出来的读**，
  不会被压成同价）。`cacheHit` 可整项省略（按 0 计），`cacheMiss` / `output` 必须写。
- `currency` 省略即人民币；写 `USD` 表示这几个数字是美元，按 `usdToCny` 折算。
- **旧格式仍然能读**：v2 的文件顶层直接就是「模型键 → 价目」，没有 `rates` 这一层。
  读到那种形状时整份当作 `rates`，`markup` / `usdToCny` 取默认值——升级插件不会
  让你已经写好的价失效。保存一次之后会改写成上面的文档式（只有一份文件，
  不该有两种写法长期并存）。

> [!IMPORTANT]
> 这里填的数会被当作**该模型的官方价**：金额按它重算，且**不再**标「估算价」。
> 因此宁可留空也不要随便填——填错的数字在界面上看不出来。
>
> 写错的条目**不会被静默忽略**：校验失败时界面会点名是哪一条、哪一项有问题
> （例如「模型「broken」 的 cacheHit 需要是一个非负数字」），并且**一个字节都不落盘**
> （下次启动不会被坏文件带坏）。

---

## 六、认不出来时：只做调用量监看

路由名认得出的模型给金额估算；**认不出的模型绝不硬塞进某个价目行**——
它会保留原名单独成行，并标**「估算价」**（暂按 Flash 单价计）。

> 把别家的模型按 DeepSeek 计价，比认不出来更糟：界面上数字有、也不报错，只是错的。

`normalizeModel` 的四层归一（大小写 / `提供商/` 前缀 / 分隔符与规范化 / 受控剥部署后缀）
能认出这些写法，它们**全是同一个模型、同一份价、同一行**：

```
deepseek-flash              官方键名
DeepSeek-Flash              大小写不同
deepseek/deepseek-flash     网关的「提供商/模型」前缀
deepseek_v4.1_flash         下划线
deepseekv41flash            连分隔符都没有
deepseek-v4-flash-ga-260731 带变体标记与发售日
hy4-preview-f               WorkBuddy 给同一个模型起的别名
```

新厂商同理：`anthropic/claude-sonnet-5-5`、`Claude-Sonnet-5.5`、`google/gemini-3.8-flash`、
`MiniMax-M3`、`x-ai/grok-4.7` 都能落到各自那一行。

### 部署 / 规格标记也认得出

自建部署（vLLM、内网网关之类）习惯在官方模型名后面接一段自己的标记，说明
**这份权重跑在哪、是哪个规格**——模型本身没变，因此折到同一行、同一份价：

| 写法 | 折到 | 含义 |
|---|---|---|
| `glm-5.3-flash-local` | `glm-5.3-flash` | 内网 / 本机自建部署 |
| `glm-5.3-flash-free` | `glm-5.3-flash` | 免费通道 |
| `glm-5.3-flash-20260101` | `glm-5.3-flash` | 权重快照日 |
| `z-ai/glm-5.3-flash-local` | `glm-5.3-flash` | 网关前缀与部署标记可以同时出现 |
| `glm-5.3-highspeed` | `glm-5.3` | 满血档的部署标记仍折到满血档 |

**判据是「官方有没有给它单独定价」，不是「名字长得像不像」。** 因此：

- `glm-5.3-flashx` 有自己的一行（官方单独定价，贵 2.5 倍），不折进 Flash；
- 只认清单里列出的那几个标记，**不做**「去掉最后一个 `-xxx` 再试」的通用回退
  （否则 `kimi-k2-thinking` 会被剥成 `kimi-k2`，将来收录 `kimi-k2` 就按「基础版」计价了）；
- 只能折进**同一族**：`deepseek-v5-local` 不会因为带个 `-local` 就被折进现行的 DeepSeek 价目
  ——「不存在的版本」必须保持认不出，否则等于替一个还没有价的模型编了一个价；
- `doubao-seed-2-0-pro`、`qwen3.6-max`、未来的 `deepseek-v5` 都保留原名并标「估算价」。

> **归一规则改进后，已有的历史会跟着更新。** 账本里存的归一键会在读取时按**当前**
> 规则重算一次（只改这一个派生字段，token 数与金额分文不动）。因此升级插件之后，
> 之前被认错的旧记录会自动归到正确的行，不必重装、也不必重扫会话日志——
> 哪怕那条会话的日志早已被删掉。

## 七、token 数量用 K / M / 亿

界面上所有 token 数都做缩略：**K 与 M 用英文**（模型文档写「128K 上下文」「1M tokens」，
用同一套单位就不必二次换算），**十亿档用中文「亿」**。

| 数量级 | 单位 | 例 |
|---|---|---|
| ≥ 1 亿 | `亿` | `13.96亿` |
| ≥ 100 万 | `M` | `617.28M` |
| ≥ 1 千 | `K` | `12.3K` |
| < 1 千 | 原值 | `999` |

注意**「亿」是 10⁸**（不是英文的 `B` = 10⁹），因此 M 档到亿档之间是 **100 倍**而不是
1000 倍：`99,999,999` 显示 `1.00亿`。

四舍五入跨过阈值时**自动升档**（`999,999` 显示 `1.00M` 而不是 `1000.0K`；
`99,999,999` 显示 `1.00亿` 而不是 `100.00M`）。

## 八、一条 = 一个模型 + 一个提供商

**模型分布**与**费用明细**里的每一条，身份都是「模型 × 提供商」，而不是模型路由名：

- **模型**按价目表归一（上面那些旧名、别名、带发售日的变体名都折到同一个模型），
  名字取**价目表里的官方名**；
- **提供商**是 DSH 里的路由（`deepseek-official`、`workbuddy-cn`、`commandcode`、`zijie` …），
  显示成它在设置里的名字。

同一个 DeepSeek Flash 经三家路由调用就是**三条用量**（倍率与额度归属不同，必须分开），
同一家路由下的多个模型别名则合成**一条**。

> **单价不按提供商拆分，而是按模型列一次。**
> 金额问的是「走官方要多少钱」，因此单价只有官方一份；同一模型的多个来源并成一条。
> 每个提供商的色块仍逐一保留，与「模型分布」环图的配色一一对应。
>
> 「模型 × 提供商」这个身份影响的是**用量与归属**（以及倍率），不是单价。

---

## 九、费用条显示谁的钱

输入框正下方那一行，**本次会话消费**一直显示（按定价表分档折算）；旁边那一枚账户事实
则**按当前会话正在用的模型来源绑定**——不会把余额与套餐并排。

| 当前模型来源 | 显示什么 |
|---|---|
| 官方 API | 官方账户余额 |
| 某家套餐（智谱 / Command Code / 火山方舟） | **那一家**最紧的额度窗口 |
| 认不出来源（新会话、或自建代理） | 你手动指定的套餐 → 官方余额 → 最紧的套餐，依次回落 |
| 绑定到了、但取不到 | 一枚「不可用」告警徽标，悬停说明原因（没配 Key / 请求失败 / 已关闭） |

**本次会话消费**与账户无关，永远显示。若这个会话用过**不在价目表里**的模型，那一枚会带一个
「估算」角标、悬停点名是哪个模型。这与看板「费用明细」里标的「估算价」是同一件事。

**套餐额度不做金额换算。** 各家额度单位互不相通（智谱是积分、Command Code 是美元信用额），
因此套餐额度只照实显示各家自己的口径，费用估算只覆盖按量计费。
