# 计费口径

> **所有金额都是「按官方单价估算」：假如这些 token 全部走 DeepSeek 官方 API，
> 分峰谷要花多少钱。** 它**不是**你的实际账单。
>
> 第三方中转与 Coding Plan（智谱 / Command Code / 火山方舟等）是**买断制**——
> 付费时一次性结清，不按 token 计费。所以它们的花费**不在此估算范围内**，
> 而不是「估算得不太准」。按 token 动态计费、余额会越用越少的只有官方 API，
> 那也正是这个估算要回答的问题。

单价与时段取自 [DeepSeek 官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
（**北京时间**）。单位：元 / 百万 token。

## 时段

**高峰时段 = 周一至周五 9:00–12:00、14:00–18:00；其余时间（含全部周末）都是空闲时段，
空闲价 = 高峰价的一半。** 费用按**每条请求发生时刻**分档计价。

界面上三处如实标注，避免把估算说成官方价：

- 价目表里没有的模型标**「估算价」**（暂按 Flash 单价计）；
- 分档定价的模型（如 GLM-4.6V）标**「按最低档」**；
- 不分时的厂商**只显示一列 token、一个单价**。

## 自己补一个价

内置价目表是随插件发布的。新模型发布得很勤，而「我用的模型没有价」的表现是它被标成
**「估算价」**并按 Flash 兜底折算——数字有、也不报错，只是错的。

补价有两个入口，改完**立刻生效**（刷新看板即可，不必重启）：

**在界面上加**——看板 →「费用明细」→ 展开「自定义单价」：

| 填什么 | 说明 |
|---|---|
| 模型键 | 与你在 DSH 里看到的模型名一致即可；大小写、`/`、`_`、`.` 都能对上 |
| 显示名 / 厂商 | 只用于展示，留空则用模型键 /「自定义」 |
| 缓存命中 / 未命中 / 输出 | 每档填**空闲**与**高峰**两个数；两格填一样的数就是不分时 |

**直接改文件**——一次补一批、或想放进版本管理：

```json
{
  "gpt-6-alstra": {
    "label": "GPT-6 Alstra",
    "vendor": "OpenAI",
    "cacheHit": { "idle": 0.5, "peak": 1 },
    "cacheMiss": { "idle": 5, "peak": 10 },
    "output": { "idle": 20, "peak": 40 }
  }
}
```

文件路径是 `$DSH_HOME/plugins/dsh-pixel-dashboard/custom-rates.json`
（`DSH_PIXEL_RATES` 可覆盖），界面里也会显示这台机器上的完整路径。

> [!IMPORTANT]
> 这里填的数会被当作**该模型的官方价**：金额按它重算，且**不再**标「估算价」。
> 因此宁可留空也不要随便填——填错的数字在界面上看不出来。
>
> 写错的条目**不会被静默忽略**：校验失败时界面会点名是哪一条、哪一项有问题，
> 并且**一个字节都不落盘**（下次启动不会被坏文件带坏）。

## token 数量用 K / M / 亿

界面上所有 token 数都做缩略：**K 与 M 用英文**（模型文档写「128K 上下文」「1M tokens」，
用同一套单位就不必二次换算），**十亿档用中文「亿」**。

| 数量级 | 单位 | 例 |
|---|---|---|
| ≥ 1 亿 | `亿` | `13.96亿` |
| ≥ 100 万 | `M` | `617.28M` |
| ≥ 1 千 | `K` | `12.3K` |
| < 1 千 | 原值 | `999` |

注意**「亿」是 10⁸**（不是英文的 `B` = 10⁹），因此 M 档到亿档之间是 **100 倍**而不是
1000 倍：`99,999,999` 显示 `1.00亿`。

四舍五入跨过阈值时**自动升档**（`999,999` 显示 `1.00M` 而不是 `1000.0K`；
`99,999,999` 显示 `1.00亿` 而不是 `100.00M`）。

## 一条 = 一个模型 + 一个提供商

**模型分布**与**费用明细**里的每一条，身份都是「模型 × 提供商」，而不是模型路由名：

- **模型**按价目表归一（下面那些旧名、别名、带发售日的变体名都折到同一个模型），
  名字取 **DSH 设置里的模型外显名**——在设置里改名，看板跟着改；
- **提供商**是 DSH 里的路由（`deepseek-official`、`workbuddy-cn`、`commandcode`、`zijie` …），
  显示成它在设置里的名字。

同一个 DeepSeek Flash 经三家路由调用就是**三条用量**（余额与套餐额度归属不同，必须分开），
同一家路由下的多个模型别名则合成**一条**；悬停模型名可以看到这一条合并了哪些路由 id。
旧版账本里没有提供商字段，插件会在下次启动时把它就地补齐；确实认不出来源的记录如实标
**「来源未知」**，而不是随便归给某一家。

> **单价不按提供商拆分，而是按模型列一次。**
> 金额问的是「走官方要多少钱」，因此单价只有官方一份；同一模型的多个来源并成一条。
> 每个提供商的色块仍逐一保留，与「模型分布」环图的配色一一对应。
>
> 「模型 × 提供商」这个身份影响的是**用量与归属**，不是单价。

## 路由名认得出就够了，不必手动配

你为**自己配的任意第三方提供商**路由模型，路由名由那家网关决定，写法五花八门。
插件不要求你填任何映射表——只要那个名字能找到价目表归属，就给出金额估算并按模型监看：

```
deepseek-flash              官方键名
DeepSeek-Flash              大小写不同
deepseek/deepseek-flash     网关的「提供商/模型」前缀
deepseek_v4.1_flash         下划线
deepseekv41flash            连分隔符都没有
deepseek-v4-flash-ga-260731 带变体标记与发售日
hy4-preview-f               WorkBuddy 给同一个模型起的别名
```

上面这些**全都认得出**是 `deepseek-flash`，同一份价、同一行。

**认不出来时就只做调用量监看**，绝不硬塞：`doubao-seed-2-0-pro`、`qwen3.6-max`、
未来的 `deepseek-v5` 都会保留原名单独成行，并标**「估算价」**——
因为把别家的模型按 DeepSeek 计价，比认不出来更糟：界面上数字有、也不报错，只是错的。

> **Token 趋势的两个维度不是同一件事，所以是切换而不是叠加。**
> 「模型」维度把同一个模型跨提供商**合并**（否则同一个模型的量会被算好几遍），
> 「提供商」维度才把它们拆开。三个维度都会与卡片上的总量对上——分维度后各条曲线
> 相加仍等于总量，超出的条目合并成一条「其他」（数字不丢）。

**套餐额度不做金额换算。** 各家额度单位互不相通（智谱是积分、Command Code 是美元信用额），
因此套餐额度只照实显示各家自己的口径，费用估算只覆盖按量计费。

## 费用条显示谁的钱

输入框正下方那一行，**本次会话消费**一直显示（按定价表分档折算）；旁边那一枚账户事实
则**按当前会话正在用的模型来源绑定**——不会把余额与套餐并排。

| 当前模型来源 | 显示什么 |
|---|---|
| 官方 API | 官方账户余额 |
| 某家套餐（智谱 / Command Code / 火山方舟） | **那一家**最紧的额度窗口 |
| 认不出来源（新会话、或自建代理） | 你手动指定的套餐 → 官方余额 → 最紧的套餐，依次回落 |
| 绑定到了、但取不到 | 一枚「不可用」告警徽标，悬停说明原因（没配 Key / 请求失败 / 已关闭） |

**本次会话消费**与账户无关，永远显示。若这个会话用过**不在价目表里**的模型，那一枚会带一个
「估算」角标、悬停点名是哪个模型。这与看板「费用明细」里标的「估算价」是同一件事。
