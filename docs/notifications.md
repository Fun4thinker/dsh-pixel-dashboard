# 通知与预警

看板里的「通知与预警」面板，以及**始终在后台运行**的通知运行时（不需要打开看板）。

| 场景 | 触发条件 |
|---|---|
| 任务完成 | 一轮对话正常跑完 |
| 失败 | 轮次报错（附错误信息与错误码） |
| 中断 / 被阻断 / 达到输出上限 / 异常结束 | 对应的结束原因 |
| 等待授权 | 工具请求授权 |
| AI 提问 | 提出待回答的问题 |
| 余额预警 | 某币种余额**低于**你设的阈值 |
| 套餐额度预警 | 某窗口「已用」**达到**你设的百分比 |

七个独立开关（面板里可逐个关掉）：总开关、任务完成、失败 / 中断、等待授权 / 回答、
余额预警、套餐额度预警、当前会话不打扰。

- **认不出的结束原因一律算失败**，绝不把一次失败说成「已完成」。
- **刷新页面不重播历史**，打开页面不会被上次会话的提醒刷屏。
- **同一项预警只提醒一次**，恢复到阈值以上后才重新武装。
- **当前会话不打扰**（默认开着）：页面有焦点、且**屏幕上正是**你看的那条会话时，它跑完不弹通知。别的会话、或你切去看板 / 别的标签页时，照常提醒（被静默的提醒仍会记进「最近通知」，不会无声消失）。

## 点通知跳回那条会话

任务完成 / 失败 / 等待授权 / 提问这类提醒都带着会话 id，因此：

- 点**系统通知** → 切到它说的那条会话；
- 点**页面内提示条** → 同上；
- 点看板「最近通知」里的那一行 → 同上。

余额 / 套餐额度预警不属于任何会话，那些行**不可点**。

> **一个已知的平台限制：点通知不会把浏览器窗口自动调到前台。**
>
> 你在别的应用里（例如最大化了别的窗口）点这条通知时，**会话一定会切过去，但窗口
> 不会自己蹦到最前面**——需要你手动切回浏览器，切回去看到的就是那条会话。
>
> 这是浏览器的安全策略，不是本插件的缺陷：`window.focus()` 按规范只是「一次请求」，
> 可能因用户设置而失败，且无法判断是否生效。浏览器故意不让脚本修改窗口的前后顺序
> （防止网页骚扰用户）。能可靠把窗口拉到前台的是 **Service Worker** 的通知通道，
> 而 DSH 的 Web 端没有注册 Service Worker——那必须由宿主产品来做，插件无法自行注册。
>
> 因此「切到那条会话」这件有保证的事照常做，「拉窗口到前台」只是尽力而为。

## 浏览器授权

系统通知需要浏览器授权。看板面板顶部有「申请授权」按钮——**必须在用户点击里申请**，
浏览器不允许插件在加载时自动弹权限框，而且一旦被拒就再也拿不回来。

授权那一行会区分**三种**「没授权」，因为下一步动作完全不同：

| 状态 | 含义 | 该做什么 |
|---|---|---|
| 未授权（`default`） | 还没问过 | 点「申请授权」 |
| 被拒绝（`denied`） | 问过并被拒 | 点「申请授权」**没用**了；去地址栏左侧的站点设置里改，再点「重新检测」 |
| 不支持（`unsupported`） | 环境没有 `Notification` API | 没有按钮可点，只能走页面内提示条 |

改了浏览器站点设置后，点一下面板上的「重新检测」就能看到状态更新，不必刷新页面。

已授权时会出现「发一条测试通知」按钮。它能弹就说明整条链路是通的；弹不出来，问题在
浏览器授权或系统勿扰上，而不是插件。

**没授权 ≠ 收不到提醒**：此时提醒会回落到页面右下角的**页面内提示条**，同时在面板的
「最近通知」里留一条。

## 阈值怎么设

- **余额**：在面板里给**每个币种**各填一个下限，留空表示该币种不预警。
- **套餐额度**：填一个「已用百分比」阈值（默认 90）。允许填 >100：官方额度用超时会给出
  >100 的百分比，「只在超限后提醒」是正当用法。填 0 表示关闭套餐预警。

两项阈值**并排一行**。「最近通知」默认收起（标题行仍写着条数），点标题行展开。
会话清单同理。
