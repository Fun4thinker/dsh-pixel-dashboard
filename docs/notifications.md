# 通知

看板设置里的「通知」页，以及**始终在后台运行**的通知运行时（不需要打开看板）。

插件的定位是**费用与用量仪表盘**，通知只是附带能力：它只覆盖「**人需要被打断**」的
那几件事。余额与额度**不在**其中——那两件事应当「想看的时候看一眼」，
所以它们改在**会话标签页**与**输入框费用条**里直接显示，不再实时通知。

| 场景 | 触发条件 | 判定在哪一侧 |
|---|---|---|
| 任务完成 | 一轮对话正常跑完 | 宿主 |
| 子智能体有进展 | 子智能体（含团队里的成员）跑完一轮；结论词是「有新进展」，失败写作「未完成」 | 宿主判定 + 浏览器换词 |
| 失败 | 轮次报错（附错误信息与错误码） | 宿主 |
| 中断 / 被阻断 / 达到输出上限 / 异常结束 | 对应的结束原因 | 宿主 |
| 等待授权 | 工具请求授权 | 浏览器 |
| AI 提问 | 提出待回答的问题 | 浏览器 |

**六个独立开关**（面板里可逐个关掉）：总开关、任务完成、子智能体进展、失败 / 中断、
等待授权 / 回答、当前会话不打扰。

## 余额与额度不再实时通知（2.14.0）

早先这里有两项阈值预警：余额低于某个值时提醒、套餐额度用到某个百分比时提醒。
它们已经**整体删除**，连同阈值输入框与两个开关一起。原因很简单：

- 余额与额度不是「必须当下处理」的事，一条随时会响的通知只会训练人把它关掉；
- 它们真正该出现的地方是**读数**：会话标签页里写着当前模型来源绑定的账户余额或
  套餐额度，输入框下方那枚费用条上也有同一个数字。

所以「我剩多少钱」现在这样看：

- **会话标签页 →「费用」**：当前会话花了多少、逐模型明细、以及当前来源的账户余额 / 套餐额度；
- **输入框下方费用条**：一眼看到本次会话金额，右边那枚就是账户余额或套餐额度。

> 旧配置文件里残留的 `warnBalance` / `warnQuotaPercent` / `notifyBalance` / `notifyQuota`
> 会在下一次读取时被归一化白名单丢掉——不会在界面上再冒出一个幽灵开关。

## 「完成」与「有新进展」是两件事

主会话跑完一轮的意思是**该你了**：模型输出完了，可以继续推进。而子智能体（含智能体团队里的
成员）跑完一轮，只是**有个成员收工了**——主会话往往还在等它，甚至还要再跑好几轮。

因此两类通知的措辞不同，这不是文案洁癖，而是**判断依据**：

| 谁的轮次结束 | 标题 | 结论词 |
|---|---|---|
| 主会话 | `目录 · 已完成` / `目录 · 失败` | 照实写结论（**不受本功能影响**） |
| 子智能体 | `目录 · 子智能体 alice 有新进展` / `目录 · 子智能体 alice 未完成` | 完成写作「**有新进展**」，失败写作「**未完成**」 |

- **能看出是哪一个**：团队里常有好几个成员，通知标题会写出团队名册里的那个名字
  （拿不到名字时只写「子智能体」，**不会**编一个假名字）。
- **正文以「进展同步」开头**，再跟细节（职责说明 · 第几轮 · 时间），所以一眼能分清
  这是进展而不是叫你回去。
- **失败也分开写**：「失败」在主会话上意思是**你的事没成**，而某个成员失败往往只是
  这一段没成——lead 可能重试、换人或带着这个空洞继续。所以子智能体的失败写作
  **「未完成」**，但仍按失败等级提醒（红框、有声音、带上错误信息与错误码）；
  其余没跑完的原因（已中断 / 被阻断 / 达到输出上限）保留原本的说法。
- **不想被进展打扰**：关掉设置里的「子智能体进展」。关掉后子智能体的完成不再弹，
  主会话完成、以及子智能体失败照旧提醒。

- **认不出的结束原因一律算失败**，绝不把一次失败说成「已完成」。
- **刷新页面不重播历史**，打开页面不会被上次会话的提醒刷屏。
- **当前会话不打扰**（默认开着）：只有你**确实正在看**这条会话时（窗口在前台、页面可见、屏幕上正是它、而且你刚在页面里动过）它跑完才不弹通知。别的会话、你切去看板 / 别的标签页、或切换到别的应用后，照常提醒（被静默的提醒仍会记进「最近通知」，不会无声消失）。

## 点通知跳回那条会话

任务完成 / 失败 / 等待授权 / 提问这类提醒都带着会话 id，因此：

- 点**系统通知** → 切到它说的那条会话；
- 点**页面内提示条** → 同上；
- 点设置里「最近通知」的那一行 → 同上。

> **一个已知的平台限制：点通知不会把浏览器窗口自动调到前台。**
>
> 你在别的应用里（例如最大化了别的窗口）点这条通知时，**会话一定会切过去，但窗口
> 不会自己蹦到最前面**——需要你手动切回浏览器，切回去看到的就是那条会话。
>
> 这是平台限制，不是本插件的缺陷：`window.focus()` 按规范只是「一次请求」，
> 可能因用户设置而失败，且无法判断是否生效。浏览器故意不让脚本修改窗口的前后顺序
> （防止网页骚扰用户）。能可靠把窗口拉到前台的是 **Service Worker** 的通知通道，
> 而 DSH 的 Web 端没有注册 Service Worker——那必须由宿主产品来做，插件无法自行注册。
>
> **桌面端（Electron）同样如此，而且更彻底**：桌面壳的 preload 只暴露了
> `bootstrap / localeChanged / open / bounds / close` 这几个与窗口相关的 IPC，
> 没有任何 `focus / activate / raise` 通道。也就是说渲染进程除了那次「请求」之外
> 别无他法。要真正解决，需要 DSH 桌面壳提供一个「把窗口提到前台」的 IPC。
>
> 因此「切到那条会话」这件有保证的事照常做，「拉窗口到前台」只是尽力而为。

## 浏览器授权

系统通知需要浏览器授权。设置面板顶部的通知页里有「申请授权」按钮——**必须在用户点击里申请**，
浏览器不允许插件在加载时自动弹权限框，而且一旦被拒就再也拿不回来。

授权那一行会区分**三种**「没授权」，因为下一步动作完全不同：

| 状态 | 含义 | 该做什么 |
|---|---|---|
| 未授权（`default`） | 还没问过 | 点「申请授权」 |
| 被拒绝（`denied`） | 问过并被拒 | 点「申请授权」**没用**了；去地址栏左侧的站点设置里改，再点「重新检测」 |
| 不支持（`unsupported`） | 环境没有 `Notification` API | 没有按钮可点，只能走页面内提示条 |

改了浏览器站点设置后，点一下「重新检测」就能看到状态更新，不必刷新页面。

已授权时会出现「发一条测试通知」按钮。它能弹就说明整条链路是通的（它走的是与真实提醒
**完全相同**的派发路径）；弹不出来，问题在浏览器授权或系统勿扰上，而不是插件。

**没授权 ≠ 收不到提醒**：此时提醒会回落到页面右下角的**页面内提示条**，同时在
「最近通知」里留一条。

## 设置里还有什么

- **开关列表**：上面那六个。
- **提示音**：跟随系统（默认）/ 关闭 / 三档内置音效 / 自定义音频地址；「试听」与真实
  通知走同一个发声函数。
- **最近通知**：最近 20 条（新在前），默认收起。被「当前会话不打扰」静默的那条也会
  列出来并标注「已静默，未弹窗」；弹窗失败的那条会写明「未弹出：原因」——
  一条记进了列表却没有任何气泡的提醒，和「功能漏了」在界面上完全一样。
- **待办**：当前等待你处理的授权 / 提问，单独放在最前面。
