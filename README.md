## 安装

用官方的 `dsh plugin add`，指向本仓库即可：

```bash
# 标准安装
dsh plugin --profile web add github:Fun4thinker/dsh-pixel-dashboard

# 卸载（自动移出 dsh.profile.bundles，不残留配置行）
dsh plugin --profile web remove dsh-pixel-dashboard

# 已发布到 npm 之后，也可以直接用包名
dsh plugin --profile web add dsh-pixel-dashboard
```

要求：Node ≥ 18。插件**没有任何第三方依赖**，也**不需要构建**——`lib/` 是随仓库提交的
构建产物，装完即可加载。

安装后**重启一次 `dsh`**，再刷新浏览器页面。

### 换电脑

不需要拷贝 `~/.dsh` 下的任何东西——那是机器本地目录。只需上面那一条安装命令：
公开仓库，不需要任何凭据。

想连用量历史一起带走，额外复制 `usage-ledger.jsonl`（见[本机数据](#本机数据)）。

### 从本地源码安装

```bash
git clone https://github.com/Fun4thinker/dsh-pixel-dashboard.git
cd dsh-pixel-dashboard
node tools/build.mjs                              # 产物写进根 lib/
node tools/install-official.mjs --profile web      # 指向本地目录，建 link: 软链
```

之后每次 `node tools/build.mjs` 都会即时生效。

## 侧栏的时段倒计时

侧栏「用量看板」那一行的右侧有一行小字，不打开看板也能一眼看到
**现在是高峰还是空闲、还有多久切换**：

```
[▮] 用量看板        2时15分后空闲期     ← 高峰中（红）
[▮] 用量看板        空闲期剩2时15分     ← 空闲中（绿）
```

两个时期各说各的话，**用颜色区分**：

| 时期 | 颜色 | 显示 | 为什么这么说 |
|---|---|---|---|
| 高峰中 | 🔴 红 | `2时15分后空闲期` | 这段是贵的，重点是**什么时候变便宜** |
| 空闲中 | 🟢 绿 | `空闲期剩2时15分` | 这段是便宜的，重点是**还能便宜多久** |

| 悬停提示 | 「用量看板 · 高峰时段 · 距转空闲 59 分 30 秒 · Asia/Shanghai」 |
|---|---|

高峰时段 = 周一至周五 9:00–12:00、14:00–18:00，其余（含全部周末）都是空闲时段。
倒计时最长会显示到天，如 `空闲期剩2天15时`（周五下班到周一早上那一段）。

排版会按侧栏宽度自动调整：

| 侧栏宽度 | 显示 |
|---|---|
| 宽 | 完整文案（`空闲期剩2时15分`） |
| 中等 | 只有时长（`2时15分`）——时期由颜色表达，省下的字留给标题 |
| 窄（收起成图标条） | 不显示 |

## 计费口径

> **所有金额都是「按官方单价估算」：假如这些 token 全部走 DeepSeek 官方 API，
> 分峰谷要花多少钱。** 它**不是**你的实际账单。
>
> 第三方中转与 Coding Plan（智谱 / Command Code / 火山方舟等）是**买断制**——
> 付费时一次性结清，不按 token 计费。所以它们的花费**不在此估算范围内**，
> 而不是「估算得不太准」。按 token 动态计费、余额会越用越少的只有官方 API，
> 那也正是这个估算要回答的问题。

单价与时段取自 [DeepSeek 官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
（**北京时间**）。单位：元 / 百万 token。

### token 数量用 K / M / 亿

界面上所有 token 数都做缩略：**K 与 M 用英文**（模型文档写「128K 上下文」「1M tokens」，
用同一套单位就不必二次换算），**十亿档用中文「亿」**。

| 数量级 | 单位 | 例 |
|---|---|---|
| ≥ 1 亿 | `亿` | `13.96亿` |
| ≥ 100 万 | `M` | `617.28M` |
| ≥ 1 千 | `K` | `12.3K` |
| < 1 千 | 原值 | `999` |

注意**「亿」是 10⁸**（不是英文的 `B` = 10⁹），因此 M 档到亿档之间是 **100 倍**而不是
1000 倍：`99,999,999` 显示 `1.00亿`。

四舍五入跨过阈值时**自动升档**（`999,999` 显示 `1.00M` 而不是 `1000.0K`；
`99,999,999` 显示 `1.00亿` 而不是 `100.00M`）。

**高峰时段 = 周一至周五 9:00–12:00、14:00–18:00；其余时间（含全部周末）都是空闲时段，
空闲价 = 高峰价的一半。** 费用按**每条请求发生时刻**分档计价。

| 模型 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
|---|---|---|---|
| `deepseek-flash` | 空闲 0.02 / 高峰 0.04 | 空闲 1 / 高峰 2 | 空闲 4 / 高峰 8 |
| `deepseek-v4-pro` | 空闲 0.15 / 高峰 0.30 | 空闲 4.5 / 高峰 9 | 空闲 13.5 / 高峰 27 |

费用明细表另外覆盖 **智谱 GLM**（单位同样是人民币 / 百万 token）：

| 模型 | 输入（缓存未命中） | 输出 | 缓存命中 | 计费方式 |
|---|---|---|---|---|
| `glm-5.3` | 8 | 28 | 2 | 不分时 |
| `glm-5.3-flash` | 0.8 | 2.8 | 0.23 | 不分时 |
| `glm-5.2` | 8 | 28 | 2 | 不分时 |
| `glm-4.6v` | 1（最低档） | 3（最低档） | 0.2 | 不分时，官方按输入长度分档 |

来源：[DeepSeek 定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、
[智谱定价页](https://docs.bigmodel.cn/cn/guide/start/pricing)。

界面上三处如实标注，避免把估算说成官方价：

- 价目表里没有的模型标**「估算价」**（暂按 Flash 单价计）；
- 分档定价的模型（如 GLM-4.6V）标**「按最低档」**；
- 不分时的厂商**只显示一列 token、一个单价**。

旧模型名（`deepseek-chat`、`deepseek-reasoner`、`deepseek-v4-flash`、`deepseek-v4.1-flash`、
`hy4-preview-f`、带发售日的 `deepseek-v4-flash-ga-260731` 等）仍可调用但按 Flash 计费，
因此统一按 Flash 计价。

### 一条 = 一个模型 + 一个提供商

**模型分布**与**费用明细**里的每一条，身份都是「模型 × 提供商」，而不是模型路由名：

- **模型**按价目表归一（下面那些旧名、别名、带发售日的变体名都折到同一个模型），
  名字取 **DSH 设置里的模型外显名**——在设置里改名，看板跟着改；
- **提供商**是 DSH 里的路由（`deepseek-official`、`workbuddy-cn`、`commandcode`、`zijie` …），
  显示成它在设置里的名字。

同一个 DeepSeek Flash 经三家路由调用就是**三条用量**（余额与套餐额度归属不同，必须分开），
同一家路由下的多个模型别名则合成**一条**；悬停模型名可以看到这一条合并了哪些路由 id。
旧版账本里没有提供商字段，插件会在下次启动时把它就地补齐；确实认不出来源的记录如实标
**「来源未知」**，而不是随便归给某一家。

> **单价不按提供商拆分，而是按模型列一次。**
> 金额问的是「走官方要多少钱」，因此单价只有官方一份；同一模型的多个来源并成一条。
> 每个提供商的色块仍逐一保留，与「模型分布」环图的配色一一对应。
>
> 「模型 × 提供商」这个身份影响的是**用量与归属**，不是单价。

### 路由名认得出就够了，不必手动配

你为**自己配的任意第三方提供商**路由模型，路由名由那家网关决定，写法五花八门。
插件不要求你填任何映射表——只要那个名字能找到价目表归属，就给出金额估算并按模型监看：

```
deepseek-flash              官方键名
DeepSeek-Flash              大小写不同
deepseek/deepseek-flash     网关的「提供商/模型」前缀
deepseek_v4.1_flash         下划线
deepseekv41flash            连分隔符都没有
deepseek-v4-flash-ga-260731 带变体标记与发售日
hy4-preview-f               WorkBuddy 给同一个模型起的别名
```

上面这些**全都认得出**是 `deepseek-flash`，同一份价、同一行。

**认不出来时就只做调用量监看**，绝不硬塞：`doubao-seed-2-0-pro`、`qwen3.6-max`、
未来的 `deepseek-v5` 都会保留原名单独成行，并标**「估算价」**——
因为把别家的模型按 DeepSeek 计价，比认不出来更糟：界面上数字有、也不报错，只是错的。

> **Token 趋势的两个维度不是同一件事，所以是切换而不是叠加。**
> 「模型」维度把同一个模型跨提供商**合并**（否则同一个模型的量会被算好几遍），
> 「提供商」维度才把它们拆开。三个维度都会与卡片上的总量对上——分维度后各条曲线
> 相加仍等于总量，超出的条目合并成一条「其他」（数字不丢）。

**套餐额度不做金额换算。** 各家额度单位互不相通（智谱是积分、Command Code 是美元信用额），
因此套餐额度只照实显示各家自己的口径，费用估算只覆盖按量计费。

## 费用条显示谁的钱

输入框正下方那一行，**本次会话消费**一直显示（按定价表分档折算）；旁边那一枚账户事实
则**按当前会话正在用的模型来源绑定**——不会把余额与套餐并排。

| 当前模型来源 | 显示什么 |
|---|---|
| 官方 API | 官方账户余额 |
| 某家套餐（智谱 / Command Code / 火山方舟） | **那一家**最紧的额度窗口 |
| 认不出来源（新会话、或自建代理） | 你手动指定的套餐 → 官方余额 → 最紧的套餐，依次回落 |
| 绑定到了、但取不到 | 一枚「不可用」告警徽标，悬停说明原因（没配 Key / 请求失败 / 已关闭） |

**本次会话消费**与账户无关，永远显示。若这个会话用过**不在价目表里**的模型，那一枚会带一个
「估算」角标、悬停点名是哪个模型。这与看板「费用明细」里标的「估算价」是同一件事。

## 账户与套餐

看板上的「账户与套餐」是一张面板并排两栏：左边官方余额，右边第三方套餐。套餐那一栏顶部
有一枚**「当前监看」切换器**：

- 选项是「自动（最紧）」加**每一家已配置的厂商**，**取数失败的那一家也会列出来**，
  方便你切过去看它的失败原因；
- 「自动」的含义就是在全部可用厂商里挑最紧的那个窗口；
- 被监看的那一家区块会带一道粉色标记与「当前监看」徽标。

这个选择只存在浏览器本地，不影响宿主是否发请求、也不影响预警判定。

## 账户余额

看板里的「账户与套餐」卡片，以及输入框正下方费用条旁的一枚余额（当来源是官方 API 时），
都来自官方 [`GET /user/balance`](https://api-docs.deepseek.com/api/get-user-balance)。

| 事项 | 说明 |
|---|---|
| 查询哪个账户 | 只查 **DSH 自己给官方 provider 用的那把 Key** 对应的账户（凭据引用默认 `DEEPSEEK_API_KEY`，可在 `llm-deepseek` 设置段里改）。暂不支持查询任意账户。 |
| 端点 | settings 段里显式配置的 `baseURL`，否则官方公网地址。 |
| 币种 | 接口返回几种就显示几种（可能同时有 CNY 与 USD），**不做汇率换算**。 |
| 刷新 | 缓存 60 秒；看板上点「刷新」会强制重取。 |
| 拿不到时 | 明确显示原因（没配 Key / 请求失败 / 已关闭），**不会**显示成 `¥0`。 |
| 关闭 | 卡片里的开关；关掉后不再发请求。`DSH_PIXEL_BALANCE=0` 可硬性关闭。 |
| 费用条那一枚 | 只在**当前模型来源是官方 API**（或来源认不出、且没手动指定套餐）时显示。走套餐时显示那一家的额度。 |

余额为负数（例如 `-¥0.79`）是官方接口真实会返回的状态，表示已欠费，界面照实显示。

## 订阅套餐额度

看板里的那一栏监控第三方 Coding Plan 的剩余额度，按窗口画进度条。
费用条旁边那一枚也用它——当**当前模型来源**属于某一家时显示那一家的最紧窗口。

| 厂商 | 窗口 | 备注 |
|---|---|---|
| 智谱 GLM Coding Plan | 5 小时、每周 | 官方**没有**月度额度，卡片里会写明 |
| Command Code | 5 小时、每周、每月 | 月度按套餐（Go `$10` / GOAT `$70` / Pro `$80` / Max …）换算成百分比 |
| 火山方舟 Agent / Coding Plan | 5 小时、每周、每月 | 自动探测两种订阅：Agent Plan 给**绝对值**，Coding Plan **只给百分比** |

### 月度那一栏是怎么算出来的（Command Code）

Command Code 的额度接口对 5 小时与每周都同时给了「已用」和「上限」，所以百分比直接算得出来；
**月度却只给一个剩余余额**（如 `$65.55`），既没有已用、也没有总额。它需要另外两个接口拼起来：

| 接口 | 给什么 |
|---|---|
| `GET /alpha/billing/credits` | 5 小时 / 每周的 `used` + `cap`，以及月度的**剩余**信用额 |
| `GET /alpha/usage/summary` | **本计费周期已用**信用额（`totalMonthlyCredits`） |
| `GET /alpha/billing/subscriptions` | **套餐身份**（`planId`，如 `individual-goat`）与计费周期 |

于是月度百分比 = 已用 ÷ （已用 + 剩余）。套餐身份决定了名义月额度，`planId` 也用在卡片上的
套餐徽标（`GOAT`）。已收录的档位与名义月额度：

| planId | 套餐 | 月额度 | 5 小时 | 每周 |
|---|---|---|---|---|
| `individual-go` | Go | `$10` | `$3` | `$6` |
| `individual-goat` | GOAT | `$70` | `$14` | `$35` |
| `individual-pro-v1` | Pro | `$80` | `$16` | `$40` |
| `individual-max` | Max 10× | `$150` | `$45` | `$90` |
| `individual-ultra` | Max 20× | `$300` | `$90` | `$180` |
| `teams-pro` | Team Pro | `$40` | `$12` | `$24` |

三条规则，都是为了让界面不撒谎：

- **拿不到「已用」就按名义额度反推**（已用 = 名义额度 − 剩余），并在卡片上标注这是推算；
- **两个接口的数对不上名义额度时，一个百分比都不给**——跨计费周期或中途换套餐时，「已用 + 剩余」
  可能来自不同周期，相加看着合理却差着几十个百分点。这一栏此时只显示 `—` 与原因；
- **未收录的套餐不做推算**：没有名义额度这把尺子，就只用「已用 + 剩余」，两者都拿不到时显示 `—`。

> 官方的额度口径随时可能变，[定价页](https://commandcode.ai/docs/resources/pricing-limits)是权威。
> 上表是 2026-09 的取值；对不上时插件会退回「只报余额」，而不是继续报一个错的百分比。

### 面板只显示你真正在用的那几家

随着接入的第三方厂商变多，全列出来会让面板越来越长，而其中大半是「你根本没配凭据」
的噪音。因此：

- **配好凭据的（或配过但出问题的）一直显示**在最上面；
- **从没配过凭据的**收进「未配置的厂商」折叠区，标题行写着有几家，点开能看到
  每一家的用途与配法——**不是删掉**，插件支持哪些家始终查得到；
- **一家都没配时折叠区默认展开**：那时上面是空的，收起会让新用户什么都看不到；
- **你正在监看、或刚在切换器里点中的那一家，永远留在上面**——点了它却在下面找不到，
  是最让人困惑的一种界面。

> 判据是「**有没有配过**」，不是「成功还是失败」。**配过但坏了**的那一家（鉴权被拒 /
> 接口失败）不会因为失败就被收起来——那正是你需要看到原因的时候。

### 这些接口是未文档化的

**三家都没有公开文档化的额度 API。** 本插件用的是它们**前端 / CLI 自己在用**的内部接口，
因此**可能随时失效**。一家失败只标那一家，其余各家与看板其余部分照常工作，
界面上也明确写「未文档化的内部接口」。

### 凭据怎么配

| 厂商 | 凭据引用 | 去哪拿 | 自动发现 |
|---|---|---|---|
| 智谱 | `ZHIPU_CODING_API_KEY` | [智谱「个人编程套餐」](https://www.bigmodel.cn/coding-plan/personal/usage) | —（智谱没有官方 CLI 凭据文件） |
| Command Code | `COMMAND_CODE_API_KEY` | [Command Code 工作台](https://commandcode.ai/studio) | `~/.commandcode/auth.json` 的 `apiKey` |
| 火山方舟 | `VOLC_ACCESS_KEY_ID` + `VOLC_SECRET_ACCESS_KEY` | [火山引擎 API 访问密钥](https://console.volcengine.com/iam/keymanage/) | —（**两把都要配**） |

拿到的值有**两种**写法，任选其一（同名即通用）：

**写法一：写进 DSH 凭据文件**（推荐）

文件是 `<DSH_HOME>/.credentials.yaml`（`DSH_HOME` 默认 `~/.dsh`），
在 `refs:` 段下按名字加行：

```yaml
version: 1
refs:
  VOLC_ACCESS_KEY_ID: AKLT...
  VOLC_SECRET_ACCESS_KEY: ...
```

DSH 会**自动重载**这个文件，因此改完不用重启——等下一次额度刷新（约 30 秒）
或点一下看板的「刷新」即可。

**写法二：设成同名环境变量**

写进 `<DSH_HOME>/.env` 或项目目录的 `.env`，或者启动 `dsh` 前 export。
这两条路都要**重启 `dsh`**：环境值在启动时就快照固定了。

优先级是**启动时环境 > 凭据文件 > 项目 `.env` > `<DSH_HOME>/.env`**。

> **为什么不能直接在「设置 → 模型」里填？**
> 那个页面只把你填的 Key 存到它自己按路由名派生的 `<路由名>_API_KEY` 之下
> （如 `VOLCENGINE_API_KEY`），而火山要的是固定的 `VOLC_ACCESS_KEY_ID` /
> `VOLC_SECRET_ACCESS_KEY`——**这两个名字不可能由那条规则推导出来**。
> 所以对火山的 AK/SK，凭据文件（或环境变量）是唯一可靠的去处。
> 看板里每一家的「这家凭据怎么配」会直接把**这台机器上的完整路径**显示出来。

Command Code 若已装 CLI 并登录过，插件会**自动读**该文件，无需额外配置；
`COMMANDCODE_HOME` 可覆盖它的目录。

> **智谱的 Key 必须是「编程套餐专属」的那一把**——在「个人编程套餐」里新建，
> 与平台普通 API Key **不通用**。用错的表现是：标准模型调用能过，但额度查询报
> `Authentication Failed`。界面上会显示凭据尾 4 位（如 `…a1b2`），便于你确认读到的
> 是哪一把。

> **火山方舟要的是另一套凭据：AccessKey ID / Secret Access Key，不是推理用的 `ark-` Key。**
> 用推理 Key 去查的表现是：网关在格式层就拒（HTTP 400 / `InvalidAuthorization` 100024）。
>
> 这两把在**火山引擎账号的 IAM** 里创建（[API 访问密钥](https://console.volcengine.com/iam/keymanage/)，
> 也常写作「访问控制 → 访问密钥」），**不在方舟控制台里**——方舟控制台给的是
> `ark-` 开头的推理 Key，正好是本接口拒绝的那一把。Secret Access Key
> **只在创建时显示一次**，记得当场下载凭证。

### 额度百分比可以超过 100

套餐额度用超时官方会给出 >100 的百分比，界面**照实显示**并单独标出「已超限」。

## 通知与预警

看板里的「通知与预警」面板，以及**始终在后台运行**的通知运行时（不需要打开看板）。

| 场景 | 触发条件 |
|---|---|
| 任务完成 | 一轮对话正常跑完 |
| 失败 | 轮次报错（附错误信息与错误码） |
| 中断 / 被阻断 / 达到输出上限 / 异常结束 | 对应的结束原因 |
| 等待授权 | 工具请求授权 |
| AI 提问 | 提出待回答的问题 |
| 余额预警 | 某币种余额**低于**你设的阈值 |
| 套餐额度预警 | 某窗口「已用」**达到**你设的百分比 |

七个独立开关（面板里可逐个关掉）：总开关、任务完成、失败 / 中断、等待授权 / 回答、
余额预警、套餐额度预警、当前会话不打扰。

- **认不出的结束原因一律算失败**，绝不把一次失败说成「已完成」。
- **刷新页面不重播历史**，打开页面不会被上次会话的提醒刷屏。
- **同一项预警只提醒一次**，恢复到阈值以上后才重新武装。
- **当前会话不打扰**（默认开着）：页面有焦点、且**屏幕上正是**你看的那条会话时，它跑完不弹通知。别的会话、或你切去看板 / 别的标签页时，照常提醒（被静默的提醒仍会记进「最近通知」，不会无声消失）。

### 点通知跳回那条会话

任务完成 / 失败 / 等待授权 / 提问这类提醒都带着会话 id，因此：

- 点**系统通知** → 切到它说的那条会话；
- 点**页面内提示条** → 同上；
- 点看板「最近通知」里的那一行 → 同上。

余额 / 套餐额度预警不属于任何会话，那些行**不可点**。

> **一个已知的平台限制：点通知不会把浏览器窗口自动调到前台。**
>
> 你在别的应用里（例如最大化了别的窗口）点这条通知时，**会话一定会切过去，但窗口
> 不会自己蹦到最前面**——需要你手动切回浏览器，切回去看到的就是那条会话。
>
> 这是浏览器的安全策略，不是本插件的缺陷：`window.focus()` 按规范只是「一次请求」，
> 可能因用户设置而失败，且无法判断是否生效。浏览器故意不让脚本修改窗口的前后顺序
> （防止网页骚扰用户）。能可靠把窗口拉到前台的是 **Service Worker** 的通知通道，
> 而 DSH 的 Web 端没有注册 Service Worker——那必须由宿主产品来做，插件无法自行注册。
>
> 因此「切到那条会话」这件有保证的事照常做，「拉窗口到前台」只是尽力而为。

### 浏览器授权

系统通知需要浏览器授权。看板面板顶部有「申请授权」按钮——**必须在用户点击里申请**，
浏览器不允许插件在加载时自动弹权限框，而且一旦被拒就再也拿不回来。

授权那一行会区分**三种**「没授权」，因为下一步动作完全不同：

| 状态 | 含义 | 该做什么 |
|---|---|---|
| 未授权（`default`） | 还没问过 | 点「申请授权」 |
| 被拒绝（`denied`） | 问过并被拒 | 点「申请授权」**没用**了；去地址栏左侧的站点设置里改，再点「重新检测」 |
| 不支持（`unsupported`） | 环境没有 `Notification` API | 没有按钮可点，只能走页面内提示条 |

改了浏览器站点设置后，点一下面板上的「重新检测」就能看到状态更新，不必刷新页面。

已授权时会出现「发一条测试通知」按钮。它能弹就说明整条链路是通的；弹不出来，问题在
浏览器授权或系统勿扰上，而不是插件。

**没授权 ≠ 收不到提醒**：此时提醒会回落到页面右下角的**页面内提示条**，同时在面板的
「最近通知」里留一条。

### 阈值怎么设

- **余额**：在面板里给**每个币种**各填一个下限，留空表示该币种不预警。
- **套餐额度**：填一个「已用百分比」阈值（默认 90）。允许填 >100：官方额度用超时会给出
  >100 的百分比，「只在超限后提醒」是正当用法。填 0 表示关闭套餐预警。

两项阈值**并排一行**。「最近通知」默认收起（标题行仍写着条数），点标题行展开。
会话清单同理。

## 本机数据

用量统计来自一份**本机账本**，默认位于：

```
$DSH_HOME/plugins/dsh-pixel-dashboard/usage-ledger.jsonl
```

每次模型请求一条记录。记录按 `sessionId:seq` 去重，因此**重复扫描不会让历史翻倍**——
重装、换机、重复导入都安全。

`DSH_PIXEL_LEDGER` 可以覆盖这个路径。余额与套餐的开关、通知阈值存在同一目录的
`balance-prefs.json`（可用 `DSH_PIXEL_BALANCE_PREFS` 覆盖），它不是历史数据，
换机时不必带走——不带就走默认值「开启」。

## 隐私与数据安全

| 事项 | 行为 |
|---|---|
| API Key | **不出本机。** 只由宿主进程从 DSH 的 credentials 服务解析，用于拼一个 `Authorization` 头；响应里只回报金额、币种与来源层名，**从不回报 Key 本身**。 |
| 浏览器端 | 永远拿不到 Key，也拿不到带 Key 的 URL。 |
| 余额请求 | 只发往 settings 里显式配置的 `baseURL`，否则发往官方 `https://api.deepseek.com`。**不读 `DEEPSEEK_BASE_URL` 环境变量**。 |
| 套餐请求 | 只发往写死的官方域名（`open.bigmodel.cn` / `api.commandcode.ai` / `open.volcengineapi.com`），不接受任何改写。Command Code 走的是它自己的三条只读路径：`/alpha/billing/credits`、`/alpha/usage/summary`、`/alpha/billing/subscriptions`。 |
| 自动发现 | Command Code 可自动读 `~/.commandcode/auth.json`（另一个 App 的密钥文件）；**只读不写**，不配置就完全不会读。 |
| 开关 | 余额与套餐各自独立开关；关掉后**一个请求都不发**。`DSH_PIXEL_BALANCE=0` / `DSH_PIXEL_PLANS=0` 可硬性关闭。 |
| 统计 | 只读本机会话日志与账本，不向任何第三方发送。 |
| 通知 | 触发提醒**不发任何网络请求**；弹的是本机系统通知。 |
| 落盘 | 只写两份本机文件：用量账本 `usage-ledger.jsonl` 与开关 `balance-prefs.json`。通知日志与「最近通知」**只在内存**。 |

无遥测、无自动上报、无外部依赖。

## 常见问题

**装完没反应 / 页面没变化？**
重启一次 `dsh`，再刷新浏览器页面（**Ctrl/Cmd + Shift + R** 强制刷新）。

**配色没生效？**
插件默认就把配色叠上了，不需要去设置里切主题。若仍是黑白，多半是没重启 `dsh`。

**余额显示「—」而不是金额？**
界面上会写明原因：没配 Key / 请求失败 / 已关闭。把「不知道」显示成 `¥0` 会让人以为余额空了，
所以这里不这么做。

**某家套餐显示「不可用」？**
那一家取数失败了，原因写在同一块里（凭据不对 / 接口变更 / 网络）。其余各家不受影响。
注意智谱要**编程套餐专属 Key**，火山要 **AK/SK**（见[凭据怎么配](#凭据怎么配)）。

**Command Code 的月度显示「—」，或者百分比看着像推算的？**
官方对月度**只报剩余余额**，没有已用与总额，所以插件得从另外两个接口拼：
「本计费周期已用」与**套餐身份**。三条相应的表现：拿不到已用时按套餐名义额度反推并标注；
两个接口的数对不上名义额度时（跨计费周期 / 中途换套餐）就不给百分比，只显示余额与原因；
未收录的套餐不做推算。详见[月度那一栏是怎么算出来的](#月度那一栏是怎么算出来的command-code)。
无论如何**都不会把「不知道」显示成 `0%`**。

**费用条旁边显示的是余额还是套餐？**
取决于当前会话正在用的模型来源，见[费用条显示谁的钱](#费用条显示谁的钱)。
想固定看某一家，用看板上的「当前监看」切换器。

**会话清单里的名字是什么？**
就是侧栏任务栏里那个标题（没生成标题时用工作目录名）。清单默认收起，
点标题行展开。

**改了代码没生效？**
宿主半边改动要**重启 `dsh`**；只改客户端则刷新页面即可。

**怎么确认装好了、跑的是哪个版本？**

```bash
node tools/doctor.mjs --profile web
```

它会告诉你插件装好没、在线版本与仓库构建是否一致、账本在哪。
